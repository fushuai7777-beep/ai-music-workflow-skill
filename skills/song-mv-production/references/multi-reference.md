# 多参考镜头制作

在镜头需要多资产、同场景接镜或参考动作节奏时使用。先确认文字分镜和素材，逐镜选择输入组合。

## 定画风后的底模与 LoRA 选型

1. **确定想改善的效果。** 根据已经定下的画风和镜头难点，明确想解决的画风、动作或细节问题。先查本地 ComfyUI 已安装的底模与 LoRA，缺合适候选时可查发布者页面。核对候选的兼容版本、节点、参考输入模式、显存要求与目标分辨率。区分风格、动作、细节增强和加速 LoRA 的用途。没有合适候选时可用已验证的配置继续。
2. **用同镜头对照。** 以当前已验证的 MiniMax H3 多图参考配置为基线。用同一镜头、参考素材、动作、目标尺寸和时长试几秒，条件允许时固定种子。比较底模时尽量保持其他条件一致，记录各模型所需的参数差异。测试 LoRA 时在同一兼容底模上对照关闭与启用。多 LoRA 先分别试过，再测试叠加，并记录实际顺序与权重。
3. **按实片决定。** 先看线条、质感、角色和道具完整性、动作、同场景一致性及实际清晰度，再用耗时和显存区分效果接近的配置。逐镜或逐类镜头采用通过对照的配置，并按[交付和审片模板](review-template.md)记录采用或保留基线的原因。

## 给输入分配用途

| 素材 | 用途 | 送入前检查 |
| --- | --- | --- |
| 干净场景图 | 固定同场景的空间、机位、光色、材质和透视 | 确认引用已定的空景版本，标明可通行区域与前后景关系 |
| 独立角色或道具图 | 约束造型、服装、比例、纹理、动作中要露出的部件 | 保存透明原层。模型输入需要 RGB 时在副本上做中性底图，保留四肢、道具和配件完整 |
| 上一镜采用的尾帧 | 提供进场位置、视线、惯性、左右方向、接触状态 | 从剪辑实际采用的版本取帧。用无字幕、无转场遮挡的对应画面，记录镜号、版本和帧号 |
| 短参考视频 | 提供局部动作、停顿、线条变化或镜头运动 | 先裁到需要学的动作，说明哪些可随参考变化，哪些沿用本镜角色和背景。只参考画面时只接图像帧 |

素材按实际接线顺序编号。每条参考都要在提示词里点明用途。发生参考冲突时，回到分镜明确以哪一版造型、位置或动作设计为准。复杂姿势用必要的中间动作图，保证接触点和重心能连起来。

## 提示词与生成选择

1. **共用要求**写画风、画幅、同场景固定信息，以及允许变化的部位。
2. **本镜输入**逐项写素材编号与作用，例如图一锁定空景、图二锁定角色、图三承接上一镜收势、视频一只参考动作速度。
3. **动作时间**写起势、关键动作、收势，以及对应歌词、鼓点或秒数。写清人物朝向、手脚或道具的接触点和镜头视角。
4. **出镜状态**写下一镜将承接的构图、动作和空间关系。多镜在一个生成段内时，为每个镜头单列时长和边界。先验证模型能按脚本切镜及维持一致性，再考虑合并生成。

多图参考可以给模型连续性提示。需要固定首尾构图时使用经过测试的首尾帧模式。栏杆前后、道具落地、脸和字形必须准确的镜头可以分层合成。线条跳帧和短暂抖动按已定画风选择，审片时确认笔触在变而角色骨架、五官和场景结构保持可辨。

## 本地 ComfyUI 接线

- 使用 **HyperFlow H3 Flash Ref2VA** 工作流时，按以下方式绑定参考。多图接入 `MiniMaxH3ReferenceToVideo` 的 `ref_images`，提示词用 `<Picture 1>`、`<Picture 2>` 等标签。支持参考视频的版本可把 `LoadVideo` 接 `GetVideoComponents`，再把 `images` 输出接 `ref_videos`，用 `<Video 1>` 引用。参考帧素材预先整理成 24 fps，优先取能说明动作的短段。切换底模时，以实际通过对照的工作流和接线为准。
- 若工作流还要使用参考音频，确认当前节点暴露相应的音频输入以及音频用途。正式合片使用锁定的原曲，生成片段的音轨按项目需求单独处理。
- 记录模型文件、提示词、参考文件、采样步数、种子和生成画布。试片按下节核对导出规格，再检查方向、遮挡、资产完整性和相邻切点。切换分辨率、时长或参考数量后重新试关键镜头。

## 试片帧数与显存记录

- **帧数和音画同步。** 记录请求的帧数或时长，从实际导出文件读取尺寸、帧率、帧数和时长。可用 `ffprobe`，帧数元数据缺失时计数解码帧。H3 节点可能对齐输入帧数，例如请求 120 帧时向上对齐到 124 帧，按 24 fps 约为 5.17 秒。按定稿音频的时间码定位剪辑位置，另记实际采用的原片入点和出点。固定帧率可记从零开始的帧号，入点包含、出点不含。可变帧率按画面时间戳。合片复查接缝和歌词动作卡点。
- **耗时和显存。** 本地试片记录总耗时，并根据日志与 GPU 监测时间戳，分别记录权重加载或换载、参考素材及提示词编码、采样、VAE 解码的耗时和显存峰值。二采能区分时分记前段、分辨率切换和后段。注明是整卡还是进程数据及采样间隔。抽样得到的最大值记为抽样峰值，无法归因的阶段记为未测。显存不足时记录失败阶段。
- **低显存候选。** 若采样阶段显存接近上限或发生显存溢出，可在测试工作流中分别对照 KJNodes 的 `MiniMax H3 Chunk FeedForward` 和 `MiniMax H3 Low VRAM Attention`。先核对当前 Flash 或 Hybrid 运行配置的兼容性，再固定底模、LoRA、参考、种子、画布、帧数和采样设置，每次只改一个节点。确认补丁实际生效，比较画风、动作、清晰度、耗时和显存，再决定是否用于正式生成。权重加载或解码达到峰值时，优先查对应阶段。
