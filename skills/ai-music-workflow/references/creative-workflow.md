# 创作修改与交接

## 从用户现有材料继续

| 输入 | 先做什么 | 不应替用户做什么 |
| --- | --- | --- |
| 方向或场景 | 整理主题、使用场景、人声、编曲主次和未定项 | 不强迫套入某种曲风或整套问卷 |
| 写好的歌词 | 读原文件，核对段落与合法重复，先做下节用字与发音校对；列出改动 | 不为适配模板重写已确认歌词，不覆盖原稿 |
| 自有录音或旋律 Demo | 明确保留旋律、换编曲还是续写；只上传获准的具体文件 | 不把文字生成称作保留原曲，不自动上传参考作品 |
| 只要提示词 | 默认直接交付英文 Styles；用户另指定语言时遵从，并保留对应歌词版本 | 不以中文方案代替英文粘贴稿，不调用生成、下载或检查无关平台状态 |
| 新方向 | 恢复总目录，在独立项目记录新需求 | 不从旧方向继承人声、配器、素材许可或生成授权 |

不要凭文件名推断实际配器、主副歌边界、速度或人声。完整解码、波形分析、音频标签、实际听审是不同证据；不支持音频理解时明确说明，仍可按用户描述写制作方案。

## 歌词用字与发音校对

有歌词时，在演唱稿交付和每次生成前先校对，不等出歌后才排查。只写 Styles 且未提供歌词时，不为此索要无关材料；无新词、已有校对记录且本轮无发音反馈时，回读该版本即可，不重复整套问答。

1. 逐句按上下文检查：错别字/同音误字、多音字、易误读词、人名地名和断句。区分“原词写错”和“原词正确但模型可能读错”；不能因字有多个读音就认定有问题。含义、专名读法或作者特殊用字不确定时，给出所在句和候选读法先问，不能猜定后提交。
2. 用户已要求提前处理发音问题时，读音明确且存在明显风险的地方，可先在独立演唱稿中用常见的同音同调字作最小提示，不改含义、字数、押韵或段落。找不到合适替字、需要换词改意或拿不准目标声调时先确认。不要把不同声调的近音字当成准确同音，也不把某次误读替换规则用于该字的所有上下文。
3. 将“原词/所在句、目标读音（含声调）、演唱提示、理由、待确认项”列成简短改动清单；没有发现问题时简短说明未发现明显风险，不承诺绝无误读。用字纠错和发音提示分别列出，不能静默混在一起。已有明确提前处理授权可完成确定的最小改法，不为每个字反复求同一范围授权；提交仍要核对实际演唱稿并取得对应版本/本批生成批准。
4. 原 Word、TXT、批准旧版本、定稿歌词与库原件不追溯修改。新演唱稿用 add-lyrics 保存新版本，真实确认后再 approve-lyrics；批次绑定该ID和内容，批准后又换字须再建版本，不改哈希或复用旧消费批准。仅对话中准备粘贴稿时无需建项目，但也要区分正式歌词与演唱提示。最终交付/素材归档保留两者区别，不把同音辅助字变成正式文学用字。
5. 出歌后对照实际听审发音、咬字、漏唱和断句；平台返回相同歌词、对齐文本或生成完成不证明已唱对。未听时明确标为待听审，不能把同音替字包装为平台必然遵从的发音控制。

| 上下文示例 | 目标读音 | 可选演唱提示 | 不能泛化的边界 |
| --- | --- | --- | --- |
| 弦乐 | xián yuè | 弦悦 | 原词“乐”本来正确，悦只为提示yuè；快乐不应跟着替换 |
| 还恩情 | huán ēn qíng | 环恩情 | 环提示huán二声；换是huàn四声，不适合作准确同音替代；还有里的还通常读hái，不套用此改法 |

表格是语境示例，不是必须替字的词典；没有相应风险时保留原词。其他明确无歧义的风险按本曲处理，不强行插入拼音、读音说明或标点到唱词使其被唱出。

### 误读清单持续记录

有用户确认位置且获准读取的私人清单时，生成前先对照；已确认私人库可从其 README 或 `Suno误读清单.md` 定位。没有库不强迫建库；用户要求建立清单时使用已确认的私人目录，未给位置先确认，不扫描全盘或固定开发者盘符。

- 用户已明确要求以后及时记录时，每次收到新的误读反馈，先在私人清单登记日期、原词与必要短句、目标读音、误读原话、来源/歌曲ID或本地记录、证据层、提示字及修正验证状态，再处理本次演唱稿。已有记账授权不反复询问；含义或读音不清只记待确认，不猜定。追加成功后回读核对，未保存成功不能声称已记录。
- 最新反馈置前，旧记录不覆盖。相同词义和错误可追加一次发生记录，不把重复反馈冒充多个独立词条；语境/目标音或替字结果不同则分开。未提供的歌曲ID、时间点或误读声调留未知，不从列表猜测。
- 用户听审报告、助手实际听审、模型/文字分析分开归因；主动预防项另列，不能当作已发生错误。已准备替字、已提交生成、替字后专项听审通过也分层；整首定稿、点赞或返回歌词一致不自动确认发音已修好。
- 对照时匹配整词和上下文，尤其同字不同音；命中后回读条件和目标声调。保留原件、正式歌词及已批准版本，只改新的演唱提示稿；未知或不适用项不替换，不自动提交生成。每次换稿重新核对发音改动清单。
- 同音提示仍收到误读反馈时，登记该版实际用字及失败，不机械复用；用户明确指定的近音或异调替字仅用于本次演唱稿，并标明与目标读音的差别。作者明确修改正式歌词时，按指定句或段落最小修改，并与演唱提示分开列出，不把正式改词当全局纠音。
- 私人清单只含必要短语和脱敏来源，不保存整首歌词、音频、凭据或签名地址，不发送第三方，也不随 Skill 分发。它是获准维护的工作日志，不自动变成 library.py 的正式可复用/可外发条目或长期个人偏好；日志授权不替代素材批准和本批消费授权。

## Suno 提示词交付格式

- 默认新写或改写的 Styles 使用英文，放在单独的 `text` 代码块中；内容是可直接粘贴的制作描述，不含中文解释、字段标题、操作步骤、Markdown 列表或未替换占位符。用户说“直接给提示词”“我来粘贴”时可以只给该块。
- 用英文明确本曲已确认的演唱语言，例如中文歌写 Mandarin Chinese vocals；唱词和标题仍保留用户原文。不要把歌词、翻译或演唱段落全文塞入 Styles；确需交付歌词时另给 Lyrics 文本块，保留原词及英文段落标签。
- 用户只要求提示词时，不强迫重贴歌词、确认项目路径、连接 Suno 或授权生成。只有缺失信息确实影响任务才问；不擅自指定演唱性别、固定 BPM 或把其他歌的风格带入。
- 中文解释与英文 Styles 分开；用户明确要双语时给两个对应且清楚区分的文本块，英文可单独复制。明确只要中文或其他语言时遵从，不强制英文。这是本工作流的默认交付约定，不是 Suno 的语言限制。
- 提交或交付前检查：英文块只含制作输入，词曲语言没有混淆，当前结构与 Lyrics 一致，已确认的人声/配器/节奏限制仍保留。涉及真实接口时按当前长度与字段限制精简，不静默截断关键要求；只准备文本不为查限制而调用平台。
- 历史原件、已提交制作包和素材库附件保留原文。将中文旧提示词转为英文供新一轮使用时另存版本，不冒称历史原始 Styles，也不扩大原有生成或素材外发授权。

## 从参考到本曲目标

只在涉及参考或主题跑偏时补充以下判断，不把每首歌都变成问卷：

- 拆开参考的用途：主题/叙述视角、编曲主体、和声与旋律走向、节奏、唱法/音色、段落动态。主参考决定用户指定的重点，辅助参考只补明确维度，不能把所有形容词堆进一条提示词。故事的地域或时代不自动决定主乐器、音阶或演唱性别。
- 链接可打开不代表已试听；自动风格摘要不等于完整配器分析或原始 Styles。用户确认摘要可作创作基底时可以继续，但标清依据与缺项，不冒称复用了原提示词或同一声音。听感、模型判断与用户描述分别归因。
- 人物叙事型主题曲可用一句话核对“谁在什么处境中，经历什么转折，最终作出什么选择”；非人物中心的作品则核对场景/群体、核心冲突或情绪落点，不硬加主角与剧情。只写已确认内容，区分原著事实、用户影片设定与助手原创延伸。无梗概且用户已同意按现有主题创作时，不反复索要剧情；不能编造未提供的事件并冒称剧情事实。
- 用户说“不扣题”时，将核心命题对应到现有歌词的动作、意象、转折或结果，找缺口和相反含义，再局部改写；不是机械加入片名、人名或主题词。副歌的关键选择与尾声的结局不能抵消用户要求的落点。
- 用户说“太直白”时，保留主题的因果和人物选择，用可感的动作、代价、画面承载；删掉解释性口号，不把角色处境删成任何故事都能套的空泛意象。若用户明确要求整稿重写，可重写，但先标清仍保留的命题与要求。

这些是创作检查方法，不是对未听参考的分析结论，也不把本次文学或旋律判断包装成已验证效果。

## 锁定本轮基准与变更

有多批同名歌曲、新词稿、新 Demo 或“沿用”要求时，先回读实际材料；必要时用一张短表确认，不另建复杂配置或改变脚本 schema：

| 项目 | 本轮要明确什么 |
| --- | --- |
| 基准 | 具体词稿版本、实际提交的 Styles，以及需要时的源音频哈希/歌曲 ID；不用最新排序、暂名或旧备忘猜身份。 |
| 保留 | 原词或新词、保留哪些旋律/结构、哪些风格维度；“沿用提示词”不自动包含同旋律或同音色。 |
| 改动 | 哪一遍、哪几句/时间区间、哪种配器或动态；新 Demo 到底替代旧源还是仅补风格参考。 |
| 放弃与待确认 | 用户明确撤销的目标从本轮约束中移除；其余已批准要求保留。仍缺的证据只问真正阻断操作的项。 |

同音色需要实际 Voice/Persona 关联证据，只有相似名字或自动风格摘要不够。用户明确放弃锁定同音色后，不继续让缺 Voice 阻塞，也不擅用任意现成 Voice；保留本轮已确认的唱法描述。只有歌词且需从头作曲时，参考风格/声音不自动改为 Cover。

新 Demo 被指定为保旋律来源时，实际请求须指向该上传源，不指向上一批文字生成结果。源 ID、续写片段 ID 和最终作品 ID 分开记录。变更说明与当前材料另存版本，已提交批次保持原样；旧日志中“尚未生成”等历史句子须结合当前清单与后续回执判断。仅交粘贴稿时在对话说明即可，不为记录而强迫创建项目。

## 生成前先确认段落设计

新歌曲或用户修改段落后，先给出一个简短结构稿：按顺序列出段落名称、所用歌词范围、是否重复或换词，以及各段的情绪和编曲变化。先区分 Verse、Pre-Chorus、Chorus、Bridge 与 Outro；以用户明确标注为准，角色不清时再确认，不因为段落位置或“副歌重复”字样就忽略内容差异。

- 用户已有完整且确认过的结构时直接回读复用，不重复询问。结构确认、曲风人声确认与一次生成授权可以在一次清楚的确认中完成；只同意结构不等于同意消费点数。
- 同旋律换词的两组副歌可标为 A/B 变体，保留两组全文；真正重复的主副歌也要展开写全，不用“重复上段”替代唱词，不去重。桥段按批准位置出现，不拿它替代未写全的第二遍副歌。
- 不强制每首歌加桥段、重复固定次数或套统一曲式。只为新曲补结构时默认不改字；删改、补词或另写桥段须明确确认。已有旋律的 Demo 要区分保留原曲式与扩展成完整歌曲，不把结构草案说成已听到的音频分段。
- 确认后的结构说明放在本项目 `inputs/`，带标签歌词用 `add-lyrics` 登记新版本并记录实际批准；不改旧歌词、旧批次或五字段 PACKAGE 模式。Style 中的结构要求须与歌词标签一致。
- 提交前逐段核对正文、重复次数、A/B 变体和桥段位置；真实生成后再听审是否遵守。返回歌词或标签一致只证明输入一致，不证明演唱结构正确。仅设计结构或准备提示词时不打开平台、不生成。
- 遇到全停、强起或对话念白，按需写清停在哪句之后、是否切尾音、有无裸声、恢复的首字或拍点；念白注明谁说、是否跟拍。必须唱出的词若漏唱，先检查括号、重叠和背景声部指令；可拆成顺序唱句并去掉冲突指令，不删补词，不把去括号当作必然修复。结构标签与 Styles 同步；验收时逐项听停顿、进入点、说话轮次与唱词完整性。

## 修改是局部的

先读本轮基准歌词和提示词，把用户新增要求落实到对应层：世界观不是乐器要求；电子节奏不是一定要改人声；加强鼓和低音不是改旋律。保存提示词新版本，保留原批次原词与参数，不倒改历史。

用户要求“少年男声”等声线时保留其语义，不默认模仿指定歌手。可用音色、咬字和唱法说明目标；不能保证提示词会被逐项执行。读取当前工具的参数限制，长 Styles 先缩短，不堆同义形容词。用“主乐器、节奏、人声、段落变化、必须避免的偏移”覆盖必要信息即可，不固定所有作品的结构。

不要主动制作合成器旋律试听、改用外部分析模型或搭建新应用；先确认这类额外交付是否有用。用户仅认可一个钩句，不等于批准全词或点数消费；用户明确要求用当前稿生成时，可登记仅限本次试作的使用批准，不声称艺术定稿。

### 把模糊反馈变成可比较的修订

先保留用户已认可的部分，只提出与投诉直接相关的少量变量；以下是可选制作手段，不是所有歌曲的默认配方或 Suno 的确定性参数。

| 反馈 | 可选修订方向 | 不应自动发生的变化 |
| --- | --- | --- |
| 副歌不抓耳 | 缩短并发展旋律动机、明确标题钩子、加强主副歌音区/节奏对比、调整句尾停留 | 擅自改词、增加唱词重复、仅靠音量变大或泛写 catchy |
| 副歌分句、和弦或调性不符 | 分开写明每遍分组与收句位置、和弦级数的参照和使用范围、预期调性中心及旋律起伏；保留重复段的歌词差异 | 把和弦级数当调性结论、补齐不同长度的副歌，或仅凭 Styles 和标签判定实际和声与分句通过 |
| 不够轻快 | 调整律动重音、切分、低音弹性、句尾拖音和伴奏密度；确需改变时再提议速度 | 直接固定更快 BPM，或把所有歌曲改成明亮舞曲 |
| 鼓和低音不够重 | 分别考虑鼓击瞬态、底鼓厚度/重音、低音音区/持续性、鼓低音配合和空间尾长；在原曲风内选手段 | 将旋律、人声、速度一并改掉，或把“厚重”理解成高密度、全程爆响、EDM drop |
| 想加电子/爵士等融合 | 明确该元素负责节奏、和声、音色还是背景，保留主体乐器与歌曲重心 | 把辅助元素升级为主曲风，或让技巧/独奏遮住人声和钩子 |

如果用户只说“完全不对”且原因不明，先定位最影响结果的维度，而不是一次同时改词、旋律、人声和编曲。已明确要求整体重做时不强行限制为微调。改法和批准范围确认后才按平台协议执行，准备文本不触发生成。

试听时优先比较本轮改变的目标：冲击是否增强、低频是否清楚、主体乐器和唱词是否仍可辨；具备条件时在近似相同感知响度下比较，不把更响当成更好。提示词改动与结果改善仅有一次对应，不能据此断言因果或推出通用最佳参数。

## 上传、Cover 与 Extend

优先核对宿主实际暴露的工具定义，不猜接口。单曲录音来源不必强制入制作人素材库；临时使用不授予长期复用。Cover、Extend 与局部动态的功能步骤统一查 [Suno 功能速查](suno-feature-guide.md)，本节只补本地材料与批次交接要求。

1. 读取用户指定的文件，确认路径、真实音频格式、时长及可解码性。发送前明确是哪份录音、给哪个平台、用来保留旋律或续写。用户已明确指定自己提供的音频用于该平台制作，无需反复问同一范围；范围不清再问。不能凭“有文件”代替权利确认，也不能代用户勾选未确认的权利声明。
2. 上传成功的 ID 是源录音，不是生成结果。保存源文件哈希、上传 ID 和状态，不保存上传凭证或签名地址；源录音未 complete 不开始改编。
3. Cover 的本地批准须对应这次源录音、实际唱词和新风格；按功能速查映射当前请求，不将保旋律目标记为已听审通过。
4. Extend 记录真实续接点与选定分支；交付目标若是整曲，另核实拼接后的完整作品身份，不把源或续段当作终版。当前无法确认秒点时不猜。
5. 本地 PACKAGE 仍只接受原来的五字段，不扩写 project.json。额外在本批 inputs 或侧边记录保存实际请求、操作类型、源 ID、目标时长等，给文件算哈希并在提交证据中引用。project.py 只校验基础包，不校验所有高级参数；提交前人工比对实际请求、源与授权。照旧执行 check-generation、预写 uncertain、一次调用、登记完整回执。

## 异常后不要让对话停在重复确认

接口超时且曲库为空，不能证明未提交；不自动重发、不新建项目解锁、不把上传源当新歌。查到新作品要核对真实身份，缺少完整批次证据时保持未决。

进行一轮有界的只读核对后，说明已知、未知、已花/未能核实的点数和缺哪一项回执，保留可用制作包。若用户要求停止检查，立即停止；不要再尝试另一浏览器或循环问“是否生成”。未知结果不会因反复批准而变成失败。

用户明确改为自己操作时交付源链接、歌词、Styles 和未决说明，不替其点击、不声称自动流程已恢复。用户返回自行生成的新链接后，可按独立结果补登记流程处理，不冒认为旧批次回执。不要为了结束等待删除未决记录或伪造 not_submitted。

## 一份可续作的记录

完成一个方向后，按用户要求在该项目留一个入口：目标与禁区、当前词稿、已接受与未定项、实际提示词、每个 Demo 的本批称呼/歌曲 ID/本地路径、后续从哪里修改。不复制签名地址、账号或全套日志；未公开歌曲不放入分发 Skill 和公开教程。歌曲材料保存与长期素材库复用是两种授权。

出歌后给本批 A/B 与真实身份的固定映射，再给少量针对本轮变化的听审点：先核对来源/保留目标，再听改动边界，最后看非目标内容是否受损及结尾完整性。平台返回 complete 只证明生成完成；用户未逐首区分的反馈记为批次反馈，不自行把 A 判通过、B 判失败。“两版都不错”可以保留两个 Demo，不强选唯一终版。

用户要求复盘写入 Skill 时，只纳入有证据支持、跨作品适用的判断方法与防错边界；先查现有规则，避免重复。具体歌词、提示词、声音偏好和单曲参数仍留项目；要进入私人制作人素材库另按其批准协议处理，不因总结项目自动入库、外发或形成全局画像。未听审与未决案例可提炼风险，不作成功效果证明。
