# AI Music Workflow Skill

版本：`0.2.1-skill-preview.20261113.1`。本次补充 Custom／Cover 分流、段落听审、歌词局部修订与定稿入库边界。保留歌词前置校对与私人误读清单、私人素材推荐、Styles 默认英文、官方功能手册、工作区前置、权限及原有脚本。仍为本地预览版，非公开稳定版，也不是旧应用的安装包。本机安装状态以实际路径、版本与回执为准。

在助手对话中完成歌曲需求整理、歌词版本确认、Suno 制作包、人工选曲和本地归档。助手优先调用宿主已连接的 Suno 官方 MCP，浏览器补缺；附带的 Python 脚本仍只管理本地记录，不调用模型 API、不登录 Suno、不生成或下载音乐。没有新增 MCP 客户端、后台服务或网络依赖。

## 使用条件

- 能发现本地 Skill、读写授权目录并运行命令的助手宿主。目前验证基线为 Windows 与 Python 3.12；其他系统或 Python 版本尚未完成验收。
- 本地脚本只用 Python 标准库。无需安装旧应用、运行本地服务器、配置 DeepSeek 等 API Key，或执行旧应用的 requirements 安装命令。
- 仅写词和整理制作包不需要平台连接。自动操作 Suno 时优先使用当前会话已连接、已授权的官方 MCP（`https://api.suno.com/mcp`）；浏览器不是 MCP 路径的前置依赖。没有对应工具时才用已授权浏览器或用户手动接管。
- MCP 连接和 OAuth 由宿主管理；本包不附带账号、密钥或令牌，也不自动改变权限。安装插件、账号显示已连接、只读调用成功、生成/下载成功是不同验收层次。
- 下载依赖平台当前提供的格式与账号权限、宿主下载能力；不保证某种格式免费或始终可用。缺少能力时可由用户操作网页和下载，助手继续管理本地材料。

## 安装与识别

1. 核对候选包文件名、版本和随包提供的 SHA-256 回执。解压后应只有一个 `ai-music-workflow` 顶层文件夹，内含下面的 12 个文件，不需要旧应用源码或私人项目数据。
2. 确认当前宿主的用户级 Skill 目录后，将整个文件夹放入其中。当前官方 Codex 文档的用户级目录是 `$HOME/.agents/skills`；已有环境若从 `.codex/skills` 识别旧安装，应先核对并复用原位置，不在两个目录重复安装同名 Skill。路径均以接收者自己的机器为准。[官方本地 Skill 说明](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。
3. 目标已存在时先停止，比较版本并备份到 Skill 扫描目录之外，得到升级确认后再替换；不要覆盖用户修改，也不要把歌曲文件放进安装目录。此候选包不是插件市场安装包。
4. 新开一个对话，使用 `$ai-music-workflow`，让助手回报实际加载的 `SKILL.md` 位置与版本。没有识别到时，检查是否多套了一层文件夹、是否重复安装；仍未出现再重启宿主并核对其 Skill 设置。文件复制完成不等于发现验收通过。

升级后也要重跑下方启动检查。若发现或启动检查失败，停止项目写入；经用户确认，保留失败副本到扫描目录之外，再恢复原安装备份，确保扫描目录内只有一份同名 Skill，并重新核对加载路径、版本和启动结果。恢复 Skill 安装不回滚、迁移或删除歌曲数据。

```text
ai-music-workflow/
  README.md
  SKILL.md
  agents/openai.yaml
  references/suno-workflow.md
  references/producer-library.md
  references/creative-workflow.md
  references/suno-feature-guide.md
  references/suno-mcp-map.md
  references/suno-official-sources.md
  scripts/project.py
  scripts/library.py
  scripts/record_io.py
```

## 第一次开始

提供歌词后，助手会先按语境检查用字及多音字，避免到出歌后才发现明显误读风险。已要求提前处理时，读音明确的风险先在独立演唱稿中做最小同音同调替字，并展示原词、目标读音和改法；原件不覆盖。不确定的含义先问，不把所有多音字都换成怪字。原词和对外歌词仍保留正式用字，实际发音须生成后听审。详见[歌词用字与发音校对](references/creative-workflow.md#歌词用字与发音校对)。

已有获准私人素材库时，可以说：“按本次需求推荐可借鉴的人声、编配或段落经验，说明来源、冲突和证据，先不采用。”助手使用现有关键词检索召回，再结合项目要求提出候选；这不是自动语义推荐。项目要求优先，长期偏好只使用制作人明确确认的记录。仅推荐不建立项目引用；选择后再登记用途，提交 Suno 还需对应授权。详见[新项目素材推荐](references/producer-library.md#新项目素材推荐)。没有库或没有合适材料，也可正常创作。

只要 Suno 提示词时可直接提中文需求，默认得到一个可粘贴到 Styles 的英文文本块，中文解释放在块外，歌词不翻译；明确要求中文或双语时按你的要求。无需先提供项目目录或连接平台。已有历史提示词与归档原件不改写。

只是查功能时可直接说：“用 AI Music Workflow 查一下如何局部改词重唱，只给步骤，先不操作。”助手先按[功能速查](references/suno-feature-guide.md)检索，不要求创建歌曲项目。该手册覆盖创作、Cover、Extend、局部替换、声音、分析、工作区、下载、分轨与 Studio；[MCP 对照](references/suno-mcp-map.md)区分当前工具与网页补缺，[官方来源](references/suno-official-sources.md)保留核对日期和差异。

可以直接说：

> 使用 $ai-music-workflow 帮我创作一首女声小清新歌曲。先问我总项目文件夹位置，只做歌词和制作包，未经我确认不要生成。

助手会先确认总目录 `ROOT`，再确定本首歌的 `PROJECT` 完整路径。没有默认盘符；首次未给路径时会先询问，已给明确路径则核对即可。目录须位于 Skill 安装目录之外；重名旧项目先决定继续还是另建。

确认目录后，助手先找到实际可用的 Python，检查版本和脚本能否启动，再检查目录写入、回读能力。以已确认的安装目录为当前目录，以下命令仅检查本地启动，不创建歌曲、不联网、不证明浏览器可用：

```text
python --version
python -I -S "./scripts/project.py" --help
```

这里的 `python` 是示例命令；若机器使用 `py -3.12` 或解释器完整路径，两条命令须使用同一个已确认解释器。命令不存在、启动器仅打开安装商店或脚本报错时，先停止本地记录流程，报告错误并确认修复方式；不要自动安装、改 PATH 或使用另一目录假装成功。纯文字讨论仍可继续，但不能声称已保存项目。

初始化 brief 由助手暂存到 `ROOT` 内、`PROJECT` 外，核对复制到项目后清理本次临时材料；不要先往待初始化单曲目录里放文件。后续材料放在 `PROJECT/inputs/`。不必手工编辑 `project.json`。

## 从创作到交付

1. 确认需求、歌词和段落设计。先看清完整顺序、每段所用歌词、哪些重复或换词、各段情绪变化，再展开带标签的歌词；不把桥段当副歌、不强制增加桥段。已经确认的结构不反复问，修改另存版本；结构或歌词批准不等于生成授权。
2. 确认制作包。进入平台步骤时检查真实工具与一次最小只读调用。按批准包映射 Custom 模式标题、风格、歌词和器乐选项；不让 Simple 模式重写定稿歌词。网页补缺时才检查页面。登录、验证码和 OAuth 授权由用户处理。
3. 新项目首次生成前核实以项目名建立的专属工作区，同项目后续沿用。明确授权本次一次生成，素材许可检查与本地待核对记录成功后才提交，工具支持时传入工作区 ID。MCP 和网页共用一次授权，结果不明先找已有结果；不能换通道、换幂等键或另建项目重复生成。兼容字段 `max_generation_clicks: 1` 在 MCP 路径表示一次创建调用。
4. 核对本批全部生成歌曲的工作区归属，人工试听并选定准确歌曲 ID。整理历史作品或迁移旧工作区须有对应授权，不因更新 Skill 自动移动。
5. 默认取得选定版本的 MP3 与 WAV。先核对可用下载方式和费用，再分别核对实际落盘、格式、歌曲来源和哈希；未取得的格式保持缺失，不用改后缀或转码冒充。
6. 按选定版本归档到 `PROJECT/final/` 下本次生成的独立目录，交付实际路径与文件链接。记录 `project_id` 以便恢复；归档复制文件，不删除输入原件。

## 可选制作人素材库

需要复用作品参考、提示词或制作经验时，另行确认素材库的完整路径与读取范围。库与单曲目录、Skill 安装目录分开，没有固定盘符。助手只处理你选中的材料，不自动扫描旧库；没有库或没有相关材料不影响原单曲流程。

新素材先存为草稿，由你对具体版本和使用范围批准后才能检索采用。读取、后续复用、提交第三方与分享分别授权；仅供本次参考不等于长期学习。查询候选后说明用途，你确认后保存项目引用，再展示实际改进的歌词或制作包。

生成前会重新核对库身份、有效版本与外发授权；停用阻止后续使用，不删除历史，也不撤回已有平台作品。更改已有素材另存新版本。音频原件可保留，但脚本不做音频理解；平台模型分析与实际试听分开记录，没有实际试听就标“未试听”，两者均未完成时标“未分析、未试听”。模型结果不自动入库。

定稿后可按你的明确要求提出经验草稿，批准后才供下一首歌参考。详细输入格式、检索、纠错和迁移方法见 [素材库操作协议](references/producer-library.md)。私人库不随 Skill 分发；本地保存不意味着云端助手读取时仍不离开本机。

## 恢复与手动接管

已有旋律时可以请求“沿用这份获准上传的 Demo，保留主副歌旋律，重做编曲”；平台可能改变细节，仍需对照听审。仅要修改提示词时不提交生成。多版下载可以命名为“歌名_demo1.mp3”“歌名_demo2.mp3”，同放本批歌词；两个 Demo 都不错不等于确定唯一终版。详见[创作修改与交接](references/creative-workflow.md)。

也可以说“这版主题跑偏了，先查歌词落点”“保持管弦和人声，只加强鼓与低音”“换用新 Demo，别误用上一批生成歌”。助手会核对保留项和本轮修改范围；风格摘要、同一音色与保留旋律不会混为同一要求。复盘方法不携带私人歌词、项目链接或固定曲风，不保证生成效果。

| 遇到的情况 | 继续方式 |
| --- | --- |
| 换对话继续 | 提供原 `PROJECT` 完整路径，让助手运行 `status` 并回读材料；不重建项目。 |
| 原目录不可访问 | 重新确认原位置、挂载或必要授权；不静默换盘。迁移需单独确认。 |
| MCP 可用、无浏览器 | 使用 MCP 已覆盖的能力，不强迫安装浏览器扩展；不支持的步骤由用户补回结果。 |
| MCP 和浏览器均不可用 | 可以继续歌词和制作包；由用户填写网页、返回普通歌曲链接和核对结果。保留原批次状态。 |
| 无自动下载能力 | 用户把平台提供的文件下载后告知真实路径，助手核对后导入；只有网页链接不算已下载。 |
| 生成结果不明 | 保持 `uncertain`，核对歌曲 ID 与来源；未查清前不再生成。 |
| 缺格式或文件损坏 | 补齐原始文件或建立正确新版本；不改清单哈希，不把不完整交付归档成通过。 |
| 文件被占用或写入持续失败 | 保留旧数据与错误回执，核对占用/路径；不放宽权限、不自动删除锁或残留。 |

运行环境检查通过只说明本地脚本可启动；只读 MCP 查询或浏览器连通不证明可生成、可下载；下载链接不等于文件已保存，解码成功不等于人工听审。WAV 或 MP3 返回额外点数要求时会暂停确认，不自动消费。反馈问题时提供本 Skill 版本、Python/宿主版本、失败步骤和脱敏错误，不上传凭据、Cookie、签名下载链接或整份私人项目。

## 验收与边界

本版验收以随包本地回执为准，区分脚本测试、隔离助手行为、真实只读调用和真人使用。MCP 协议根据当前宿主加载的官方工具定义编写，不等于已经跑过真实生成、工作区写入或双格式下载。用户于 2026-10-17 报告旧预览版已通过换机真人测试；这不是新增素材库或 MCP 路径已经换机验收的证据。

换机试用时至少核对：只按本文安装即可识别；先询问保存位置；中文与空格目录可写；新对话能恢复同一项目；无浏览器时能手动接管；选定歌曲的要求格式齐全后才能归档。由真实使用者确认听审质量与最终交付。

新增素材库尚待用户指定真实材料完成“两首歌经验复用”验收。Skill 不承诺 Chrome 扩展、平台登录、生成质量或下载权益；不能把本地归档当成公开发布。公开发布、付费、账号/权限修改、全局安装升级、旧项目迁移及删除仍需单独授权。项目材料、私人日志和公开视频脚本不属于分发内容。

维护入口：[助手操作规则](SKILL.md)、[Suno 操作与中断恢复](references/suno-workflow.md)。旧应用与其 README 独立保留，使用本 Skill 不需要启动旧应用。
